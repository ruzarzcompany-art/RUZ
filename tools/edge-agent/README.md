# جهاز التحليل المباشر

برنامج يعمل على جهاز صغير داخل المطعم، يقرأ بث الكاميرات من جهاز التسجيل
(Hikvision) على الشبكة المحلية ويكشف الأشخاص باستمرار، ويتابع ما رُسم في
«سِجل ← الرقابة والكاميرات ← التنبيه والتصعيد ← مناطق التحليل المباشر»:

| المنطقة | ما يُرصد | الحدث |
| --- | --- | --- |
| طاولة | جلس عملاء وانتهت المهلة والطلب لم يصل للطاولة | تنبيه واحد «تأخّر طلب العميل» للمشرف مع 3 لقطات |
| طاولة | فضيت وانتهت مهلة تنظيفها | لقطة للطاولة ← يتحقق منها الخادم ← تنبيه «طاولة متسخة» |
| طابور الكاشير | عدد الواقفين فوق الحد لمدة متصلة | تنبيه «طابور طويل» |
| منطقة ممنوعة | شخص داخلها خارج ساعات العمل | تنبيه فوري للمالك |
| خط الباب | عدد الداخلين والخارجين كل ساعة | نسبة الشراء في التقرير الليلي |

الفيديو لا يغادر المطعم: يُرسل للخادم الحدث فقط مع تسلسل صور قصير دليلاً
(لقطتان قبل الحدث بثوانٍ + لقطة لحظة الحدث) يظهر في التنبيه والتقرير المصوّر. وإذا
انقطع الجهاز 5 دقائق (فُصل عن الكهرباء أو الشبكة) يصل المالك تنبيه.

## كيف يتابع طلب الطاولة؟

العميل يطلب من الكاشير ثم يجلس، فالجلوس معناه أن الطلب قيد التجهيز. لكل جلسة:

1. **عند الجلوس** (بعد 20 ثانية وجود متصل): لقطة تبقى في الجهاز.
2. **بعد نصف المهلة** (5 دقائق إن كانت المهلة 10): لقطة للطاولة نفسها يتحقق منها
   الخادم — هل وصل الطلب؟ إن وصل انتهت المتابعة وسُجّل الطلب «سريعاً».
3. **عند نهاية المهلة** (10 دقائق): لقطة أخيرة. إن وصل الطلب سُجّل «في الوقت»، وإن
   لم يصل خرج **تنبيه واحد** للمشرف بتأخير الطلب ومعه اللقطات الثلاث.

وقوف موظف عند الطاولة لا يُحسب وصولاً للطلب — الحكم لما يظهر على الطاولة في اللقطة.
وإن غادر العملاء قبل موعد اللقطة فلا تحقق ولا تنبيه. تقييم السرعة اليومي (سريع /
في الوقت / متأخر) يظهر في «سِجل ← التنبيه والتصعيد» وفي التقرير الليلي.

## المتطلبات

- جهاز يعمل دائماً وموصول بسلك بنفس شبكة جهاز التسجيل: ميني PC بمعالج Intel
  حديث و8GB ذاكرة يكفي لبضع كاميرات على إطارين في الثانية. الجوال لا يصلح.
- يوضع في مكان مقفل (مع جهاز التسجيل) حتى لا يُفصل.
- Python 3.12 (على ويندوز: `py install 3.12` ثم `py -3.12 -m venv .venv`).
- على ويندوز جديد: ثبّت Microsoft Visual C++ Redistributable (x64) أولاً، وإلا يفشل
  تحميل torch بالخطأ `WinError 126 … shm.dll`.

## التركيب

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt     # ويندوز: .venv\Scripts\pip
cp config.example.json config.json            # ثم عدّله
.venv/bin/python agent.py --check             # يفحص الخادم وكل كاميرا ويرفع لقطة معاينة
```

في `config.json`:

- `agentKey`: نفس قيمة `SURVEILLANCE_WEBHOOK_SECRET` في Netlify.
- `branchCode`: رمز الفرع في «سِجل».
- `nvr`: عنوان جهاز التسجيل على الشبكة المحلية واسم المستخدم وكلمة المرور
  (تبقى على هذا الجهاز فقط ولا تُرسل للخادم). `stream: 2` = البث الفرعي.
- `cameras`: رقم الكاميرا كما في «سِجل» ← رقم قناتها في جهاز التسجيل.

بعد `--check` تظهر لقطة كل كاميرا في «سِجل»، فتُرسم عليها المناطق. ثم:

```bash
.venv/bin/python agent.py
```

للتشغيل الدائم: `start-windows.bat` (يوضع في «بدء التشغيل»)، أو
`sijil-edge.service` على لينكس.

## رسم المناطق

- **الطاولة:** مضلّع على سطح الطاولة نفسه (لا الكراسي) — البرنامج يوسّعه ليشمل
  الجالسين. طاولة يحجبها عمود أو تظهر من زاوية حادة جداً تُترك بلا رسم.
- **الطابور:** المساحة التي يقف فيها العملاء أمام الكاشير (تُحسب الأقدام).
- **خط الباب:** نقطتان عبر عتبة الباب. الدخول = العبور نحو أسفل الصورة حين
  يُرسم الخط من اليسار إلى اليمين؛ وإن انعكس العدّ يُرسم بالعكس.
- **المنطقة الممنوعة:** أرضية المستودع أو مدخل الباب الخلفي.

## الضبط في الأيام الأولى

المهل (وصول الطلب للطاولة، تنظيفها، الطابور) تُضبط من «سِجل». جرّب أسبوعاً وراجع
اللقطات المرافقة للتنبيهات: إن كثرت التنبيهات الخاطئة لطاولة فأعد رسمها.

للتجربة على مقطع مسجَّل بلا خادم:

```bash
python agent.py --source clip.mp4 --zones zones.json --out events/ --verbose
```

و`zones.json` بالصيغة:
`{"zones":[{"id":1,"kind":"table","label":"4","points":[[0.3,0.2],[0.6,0.2],[0.6,0.5],[0.3,0.5]]}]}`

اختبار المنطق وحده: `python test_logic.py`.

## الأداء

`yolo11n.pt` أخف نموذج. إن تأخر التحليل: قلّل `fps` إلى 1، أو حوّل النموذج إلى
OpenVINO لمعالجات Intel (`yolo export model=yolo11n.pt format=openvino`) وضع
`"model": "yolo11n_openvino_model"`.
