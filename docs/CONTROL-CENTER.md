# مركز الضبط — التنبيه والتصعيد عبر واتساب

تبويب «التنبيه والتصعيد» داخل «الرقابة والكاميرات». يأخذ كل تنبيه رقابي
(من الكاميرات أو فوديكس أو الإدخال اليدوي) ويبلّغ صاحبه على واتساب، ويصعّده
إن لم يؤكَّد استلامه.

## من يستلم ماذا

| المجموعة | الأنواع | يستلم أولاً | التصعيد |
| --- | --- | --- | --- |
| سرقات وخلل كبير | فتح الدرج بلا بيع، طلب بلا فاتورة، تكرار الإلغاء/الخصم، إخراج مواد، دخول المستودع خارج الدوام، فرق المبيعات، فرق الجرد، توقف/تحريك كاميرا | المالك | — |
| الخدمة | طاولة متسخة، شكوى طاولة (QR)، انتظار عميل، تأخر طلب، طابور الكاشير، باب ثلاجة مفتوح | الموظف | المدير ثم المالك |
| الإدارة | تقييم قوقل السيئ، نقاش مع عميل، مغادرة عميل، إرجاع طلب، مخالفة نظافة أو زي | مدير المطعم | نقاش العميل فقط يصعَّد للمالك |
| ملاحظات بسيطة | جوال، ترك محطة، تجمع، هدر مرصود | التقرير الليلي فقط (أو المدير فوراً إن فُعّل الخيار) | — |

- المهل الافتراضية: الموظف دقيقة واحدة (دقيقتان لتأخر الطلبات)، المدير 3 دقائق.
  الفحص الدوري كل دقيقة (`netlify/functions/control-tick.mts`)، فأقل مهلة دقيقة.
- إن لم يوجد في المستوى مستلم متاح (لا موظف على رأس العمل مثلاً) ينتقل التنبيه
  فوراً للمستوى الأعلى.
- حالات الاشتباه لا تُرسل للموظفين، وكل رسالة عنها تحمل «اشتباه يحتاج مراجعة».
- تأكيد الاستلام: رابط في الرسالة يفتح صفحة `/app/ack/` بزر «استلمت التنبيه».
  فتح الرابط وحده (أو معاينة واتساب له) لا يؤكد شيئاً. حسم التنبيه بالمراجعة
  داخل النظام يوقف التصعيد أيضاً.
- حد أمان: 15 رسالة لكل مستلم في 10 دقائق، والأحداث الأقدم من 6 ساعات لا تُبلَّغ.

## التحليل المباشر للطاولات (جهاز داخل المطعم)

الكشف الدوري باللقطات (كل بضع دقائق) لا يستطيع أن يعدّ «5 دقائق بلا موظف» ولا
«دقيقة بعد المغادرة». لذلك أُضيف جهاز تحليل يعمل داخل المطعم
(`tools/edge-agent`): يقرأ بث الكاميرات محلياً، يكشف الأشخاص باستمرار، ويعدّ
لكل طاولة مرسومة. لا يرسل للخادم إلا عند الخلل مع لقطة واحدة دليلاً، فلا تكلفة
ذكاء اصطناعي إلا للتحقق من لقطة الطاولة التي فضيت.

1. تُرسم المناطق من التبويب: «التحليل المباشر» ← اختر الكاميرا ← انقر زوايا
   الطاولة ← رقمها ← حفظ. الأنواع: طاولة، طابور الكاشير، خط الباب، منطقة ممنوعة.
2. المهل من الإعدادات: «عميل جالس بلا موظف»، «مهلة تنظيف الطاولة»، «مدة الطابور».
3. الأحداث تدخل نفس مسار التوجيه والتصعيد: `customer_wait` و`dirty_table`
   و`cashier_queue` للموظف ثم المدير ثم المالك، و`warehouse_off_hours` للمالك.
4. تُحفظ كل جلسة طاولة (وقت وصول الموظف، وقت التنظيف) وعدد الداخلين من الباب،
   وتدخل في التقرير الليلي.
5. انقطاع الجهاز 5 دقائق يُنبَّه عنه المالك مرة واحدة.

التركيب والمتطلبات في [`tools/edge-agent/README.md`](../tools/edge-agent/README.md).

## إعداد واتساب (مطلوب مرة واحدة)

### الخيار الرسمي: WhatsApp Cloud API من Meta

1. أنشئ تطبيقاً في Meta for Developers وأضف منتج WhatsApp، واربط رقماً للمطعم
   (رقم غير مستخدم في تطبيق واتساب العادي).
2. أنشئ قالب رسالة باسم `sijil_alert`، الفئة Utility، اللغة Arabic (`ar`)، ونصه:

   ```
   إشعار من نظام سِجل لإدارة المطعم:
   {{1}}
   هذه رسالة آلية.
   ```

   وانتظر اعتماده من Meta.
3. أنشئ System User Token دائماً بصلاحية `whatsapp_business_messaging`.
4. في Netlify ← Environment variables:

   | المتغيّر | القيمة |
   | --- | --- |
   | `WHATSAPP_TOKEN` | التوكن الدائم |
   | `WHATSAPP_PHONE_ID` | Phone number ID من لوحة Meta |
   | `WHATSAPP_TEMPLATE` | اختياري — الافتراضي `sijil_alert` |
   | `WHATSAPP_TEMPLATE_LANG` | اختياري — الافتراضي `ar` |
   | `WHATSAPP_API_VERSION` | اختياري — الافتراضي `v23.0` |

متغيّر القالب لا يقبل أسطراً، فتُرسل الرسالة سطراً واحداً بفواصل « • ».

### بديل: UltraMsg (غير رسمي)

`WHATSAPP_PROVIDER=ultramsg` مع `WHATSAPP_INSTANCE` و`WHATSAPP_TOKEN`. يرسل نصاً
حراً بلا قالب، لكنه بوابة غير رسمية وقد يُحظر الرقم المستخدم.

## تقييمات قوقل

تُسحب كل 15 دقيقة عبر Google Business Profile API (v4 reviews)، وأول مزامنة تسجّل
الموجود بلا تنبيه. يلزم:

1. مشروع Google Cloud مفعَّل فيه Business Profile API (يتطلب تقديم طلب وصول من
   قوقل والموافقة عليه).
2. OAuth Client (Web) ورمز تحديث `refresh_token` لحساب مالك النشاط بالصلاحية
   `https://www.googleapis.com/auth/business.manage`.
3. في Netlify: `GOOGLE_CLIENT_ID` و`GOOGLE_CLIENT_SECRET` و`GOOGLE_REFRESH_TOKEN`.
4. في التبويب: «موقع النشاط في قوقل» بالصيغة `accounts/{id}/locations/{id}`.

## شكاوى الطاولات (QR)

زر «طباعة رموز QR للطاولات» يولّد رمزاً لكل طاولة يفتح
`/app/feedback/?b=<رمز الفرع>&t=<رقم الطاولة>`. الشكوى تُسجَّل تنبيهاً من نوع
`table_complaint` وتذهب لموظف الصالة ثم تُصعَّد. الحدود: شكوى واحدة للطاولة في
الدقيقة، و30 للفرع في 10 دقائق.
