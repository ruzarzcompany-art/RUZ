# نظام تقفيل الكاشير والنقدية

إضافة كاملة على النظام القائم: سجل موحّد للمصاريف والمشتريات النقدية، المتبقي
النقدي في درج الكاشير، الرصيد النقدي الشهري، تسوية الشبكات وتطبيقات التوصيل،
وإقفال الشهر بترحيل الصافي أو تصفيره — بصلاحيات مستقلة وسجل مراجعة لكل قرار.

**شرط التنفيذ المحفوظ:** لم يُعدَّل أي جدول قائم ولا أي صف محفوظ. أربعة جداول
جديدة فقط، والمتبقي والصافي يُحسبان **قراءةً وقت العرض** — فلا مبلغ مخزَّن
مرتين ولا خصم مزدوج، والتقفيلات السابقة تبقى بأرقامها حرفياً. النسخة الاحتياطية
وخطوات الرجوع في `docs/BACKUP-BEFORE-DEPLOY.md`.

## 1) السجل الموحّد للمصاريف والمشتريات النقدية

جدول `cash_expenses`: كل عملية دفع نقدي فاتورة مستقلة بحقولها — البيان (غاز،
دجاج، لبن…)، رقم الفاتورة، الكمية، سعر الوحدة، المبلغ الإجمالي، التاريخ، الوردية،
النوع (`expense` مصروف تشغيلي أو `purchase` شراء بضاعة)، المورد، من سجّلها.

- **تُسجَّل مرة واحدة:** فهرس فريد جزئي على (الفرع + رقم الفاتورة) يرفض تسجيل
  الرقم نفسه مرتين، والخادم يرد برسالة تذكر تاريخ التسجيل الأول ومبلغه. والفواتير
  بلا رقم (نثريات) لا يقيّدها الفهرس.
- **تُخصم مرة واحدة:** لا عمود مخزَّن للمصاريف في التقفيلة ولا في الشهر؛ تقفيل
  اليوم والتقرير الشهري يقرآن مجموع الفواتير من هذا الجدول وقت العرض.
- المبلغ الإجمالي = الكمية × سعر الوحدة، وإن أُدخل مبلغ صريح (ضريبة/خصم/تقريب)
  فهو المعتمد لأنه ما خرج من الدرج فعلاً.

## 2) المتبقي النقدي في التقفيلة

```
المتبقي النقدي = المبيعات النقدية − مصاريف نفس اليوم/الوردية
```

يظهر في ثلاثة مواضع: شاشة تقفيل الكاشير في لوحة الإدارة، شاشة «تقفيل الكاشير»
في تطبيق الموظف، وسجل التقفيلات (عمودا «مصاريف السجل» و«المتبقي») مع مجموعه في
شريط الملخّص. توزيع المصاريف على الورديات: التقفيلة الوحيدة في يومها تأخذ مصاريف
اليوم كلها، وإن تعدّدت التقفيلات أخذت كل واحدة مصاريف ورديتها وحدها — فلا يُخصم
مصروف في تقفيلتين.

حساب التقفيلة القائم (`expectedCash` و`difference`) لم يُلمس، والمتبقي حقل قراءة
إضافي بجانبه.

## 3) الرصيد النقدي الشهري

```
الصافي الحالي = المرحّل من الشهر السابق + النقدي المتراكم من التقفيلات
                − المصاريف والمشتريات النقدية
```

يُعرض طوال الشهر لا في نهايته فقط (`GET /api/finance/monthly-balance`) مع تفصيل
يوم بيوم، ومعه عمولات التسويات المؤكَّدة وضريبتها وحالة الشهر.

## 4) تسوية الشبكات وتطبيقات التوصيل

مبيعات كل جهة تُرصد أولاً في بنود التقفيلة (شبكات، فودكس، تطبيقات توصيل)، ثم
تُبنى منها شاشة التسوية بلا إدخال يدوي لرقم المبيعات. وعند وصول المبلغ للبنك
يؤكّد المحاسب السداد ويُدخل المستلم فقط:

```
العمولة        = المبيعات − المستلم
النسبة المئوية = (العمولة ÷ المبيعات) × 100
الضريبة        = اختيارية على العمولة (شاملة داخلها أو مضافة فوقها)
```

كل تسوية تُسجَّل في `provider_settlements` بـ: الجهة ونوعها، المدة، المبيعات،
المستلم، العمولة، النسبة، نسبة الضريبة ومبلغها، العمولة قبل الضريبة، تاريخ
التأكيد، واسم المحاسب (لقطة نصّية تبقى ولو تغيّر ملفه). المؤكَّدة لا تُعدَّل.

## 5) إقفال الشهر والترحيل

- عند فتح شاشة الإقفال يجهّز النظام تلقائياً ملخّص كل شهر انتهى ولم يُجهَّز:
  الإجمالي النقدي، المصاريف، الصافي — ويُرسل إشعاراً (`cash_notifications`)
  للأونر ولكل من يملك «اعتماد الترحيل» أو «التصفير» أو «عرض ملخص الإقفال».
- الشهر يبقى بحالة **بانتظار الاعتماد** ولا يُعدّل عليه: `locked_at` يمنع أي
  كتابة على تقفيلات الشهر أو فواتيره أو تسوياته (409 برسالة واضحة).
- أمام صاحب الصلاحية زرّان بضغطة واحدة: **اعتماد الترحيل** فيصبح الصافي رصيد
  بداية الشهر الجديد تلقائياً، أو **تصفير** فيبدأ الشهر الجديد من صفر.
- الشهر المُقفل لا يُعاد فتحه، وكل قرار يُكتب في `audit_logs` بالقيم قبل وبعد:
  من، متى، ماذا اختار، وكم رُحّل إلى الشهر التالي.

### الصلاحيات (بنود مستقلة بخانة صح)

| البند في شاشة «إدارة الصلاحيات» | الرمز | الأثر |
| --- | --- | --- |
| عرض ملخص الإقفال | `monthly.summary_view` | يرى الملخّص والرصيد الشهري بلا أي قرار |
| اعتماد الترحيل الشهري | `monthly.carry_forward` | يظهر زر «اعتماد الترحيل» وينفّذه |
| تصفير الرصيد الشهري | `monthly.reset` | يظهر زر «تصفير» وينفّذه |
| المصاريف والمشتريات النقدية | `cash_expenses.read/write` | درجات 1..3 + خانة حذف مستقلة |
| تسوية الشبكات وتطبيقات التوصيل | `settlements.read/manage/confirm` | درجات 1..4 (التأكيد في الرابعة) + حذف |

الأونر (من يملك بند «إدارة الصلاحيات» بدرجة التعديل) يملك البنود الخمسة
افتراضياً عبر منح أوّلي idempotent في `ensureCashClosingGrants()`، ويمنحها أو
يسحبها بعدها لأي موظف من شاشة «إدارة الصلاحيات» — والبذر لا يعود فيكتب ما عُدِّل.
من لم تُمنح له البنود **لا يرى الأزرار إطلاقاً**، والخادم يرفض طلبه لو استدعى
المسار مباشرة (403 برسالة البند المطلوب).

```
[ناجح] app.ts يركّب financeRouter على /api

[ناجح] db/schema.ts بلا أي ALTER — إضافة أربعة جداول فقط
[ناجح] sw.js يحتوي cashbox.js وإصدار القشرة v15 مطابق لـAPP_VERSION
```

### ب) تقفيلة بمصاريف مفصّلة

فواتير اليوم: غاز 1×90، دجاج 12×23.5، لبن 6×7.25، خضار بمبلغ صريح 27.5.

```
الفواتير: 90 + 282 + 43.5 + 27.5 = 443
مبيعات نقدية 4200 → المتبقي النقدي = 3757
قراءة ثانية للمتبقي = 3757  (لا خصم مزدوج)
إعادة تسجيل نفس رقم الفاتورة → 409: «مسجّلة مسبقاً … تُسجَّل مرة واحدة وتُخصم مرة واحدة»
```

### ج) تسوية شبكة بعمولة وضريبة

```
فوديكس: مبيعات 10000 — مستلم 9750
  العمولة = 250 · النسبة = 2.5%
  ضريبة 15% شاملة → الضريبة 32.61 والعمولة قبل الضريبة 217.39
  ضريبة 15% مضافة فوق العمولة → 37.5
بلا ضريبة: عمولة 200 بنسبة 2.5% وضريبة 0
التسوية تُقفل بحالة «مؤكَّدة» مع تاريخ التأكيد واسم المحاسب، ولا تُعدَّل بعده
```

### د) إقفال شهر باعتماد الترحيل

```
يوليو: 0 + 60000 − 12500 = 47500 → الحالة carried_forward · المرحّل 47500
أغسطس يبدأ من 47500 → صافيه 47500 + 30000 − 5000 = 72500
الشهر مقفل: أي تعديل على تقفيلة أو فاتورة أو تسوية فيه يُرفض بـ409
سجل المراجعة: month.carry_forward — من، متى، القيم قبل وبعد، والمرحّل للشهر التالي
```

### هـ) إقفال شهر بتصفير

```
يوليو الصافي 47500 → الحالة reset · المرحّل 0
أغسطس يبدأ من 0 → صافيه 25000
سجل المراجعة: month.reset بنفس التفاصيل، والشهر لا يُعاد فتحه
```

### و) موظف بدون صلاحية يحاول الترحيل

```
[ناجح] البنود الثلاثة خانة صح واحدة لكل بند (بلا سلّم درجات وبلا خانة حذف)
[ناجح] «عرض ملخص الإقفال» لا يمنح الترحيل ولا التصفير
[ناجح] «اعتماد الترحيل» لا يمنح التصفير، و«التصفير» لا يمنح الترحيل
[ناجح] من لا بند له: لا رمز إطلاقاً → بطاقة الإقفال مخفية كلياً
[ناجح] الواجهة لا تبني الزر إلا بصلاحيته، وتضع مكانه «بانتظار صاحب الصلاحية»
[ناجح] الخادم يفحص رمز القرار نفسه: 403 «لا تملك صلاحية اعتماد الترحيل الشهري»
        أو «لا تملك صلاحية تصفير الرصيد الشهري» — حتى لو استُدعي المسار مباشرة
```

التشغيل المحلي للفحص الذاتي:

```
npm run test:finance
```

## ما يبقى على البشر قبل النشر

1. أخذ النسخة الاحتياطية حسب `docs/BACKUP-BEFORE-DEPLOY.md` (لقطة Neon + `pg_dump`).
2. النشر يطبّق الترحيل الجديد فيُنشئ الجداول الأربعة.
3. تشغيل `npm run test:finance` و`npm run typecheck` محلياً.
4. من شاشة «إدارة الصلاحيات»: منح البنود الخمسة لمن يستحقها من الموظفين.
5. التحقق من أن شهراً سابقاً لا يظهر «بانتظار الاعتماد» إلا بعد تجهيزه فعلاً.
